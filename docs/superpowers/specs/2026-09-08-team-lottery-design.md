# 企业团队抽签网页需求

## 结论

2026-09-09 修订：名单变更、暂停成员、改组名及重复导入保留本轮历史与已抽记录，新增成员可参与。只有明确重置或清空才删除记录。完整顺序为独立排序；关闭允许重复后避开本轮全部已抽对象。导入增加预览与逐行错误提示，错误未修正时禁止写入。新历史记录保存完整对象快照。

第一版做成无需登录、打开即用的静态网页。组织者在浏览器内建立“小组—成员”名单，随后通过全员抽人、指定组抽人、抽小组、先抽组再抽人四种模式完成团队内部的随机选择。名单和抽取进度仅保存在当前浏览器，不上传服务器。

## 使用场景

- 从全部员工中随机选择一人或多人承担任务、回答问题或发言。
- 从指定小组中随机选择一人或多人。
- 从多个小组中随机选出一个或多个小组，决定汇报或行动顺序。
- 先随机选出一个小组，再从该小组中随机选择一名成员。

账号体系、企业通讯录、多人实时协作、随机分组和服务端审计不进入当前版本。

## 用户流程

1. 用户打开网页，先看到名单编辑区和抽签控制台。
2. 用户新建小组，填写组名，并通过换行、逗号或顿号批量录入成员。
3. 网页即时展示有效小组数、成员数和重复姓名提示，并把名单自动保存在本地。
4. 用户选择抽签模式、抽取数量和是否允许重复。
5. 用户点击“开始抽签”，页面经过短暂滚动动画后展示结果。
6. 用户可以继续抽取；默认情况下，同一轮已抽中的对象不会再次出现。
7. 用户可以查看本轮历史，或重置本轮让全部对象重新参与。

## 功能要求

### 名单管理

- 默认提供两个空白小组，用户可添加、重命名和删除小组。
- 每个小组用一个多行输入框录入成员，支持换行、中文或英文逗号、顿号和分号分隔。
- 自动去除首尾空格和空项；同一小组内重复姓名只保留一次。
- 不要求员工拥有唯一账号。同名员工通过所属小组区分；同一组内的同名记录视为重复输入。
- 名单自动写入浏览器 `localStorage`，刷新后恢复。
- 提供“清空名单”，执行前需要二次确认。

### 抽签模式

- `全员抽人`：合并所有小组成员后抽取，可选择 1 至候选人数个结果。
- `指定组抽人`：用户先选择小组，再从该组成员中抽取。
- `抽小组`：从所有非空小组中抽取，可选择一个或多个结果。
- `先抽组再抽人`：先抽出一个非空小组，再从该组抽出一名成员。
- `生成完整顺序`：一次性生成全部有效员工或全部有效小组的随机顺序。
- 默认“不重复抽取”。关闭后，每次抽签都从完整候选池中抽取，但同一次抽取内仍不能产生重复结果。
- 全员抽人时每位员工机会相同；先抽组再抽人时每个有效小组机会相同。
- 先抽组再抽人时，抽中的成员退出本轮，小组仍可继续参与，直到组内没有可抽成员。
- 候选数不足、没有小组、所选小组为空时，禁止开始并明确说明原因。

### 公平性与展示

- 使用浏览器密码学随机源 `crypto.getRandomValues()` 选择结果，避免使用 `Math.random()`。
- 抽签前展示当前模式和有效候选数量；动画只负责展示，不参与结果计算。
- 结果区同时显示姓名和所属小组，抽小组时只显示组名。
- 页面提供本轮历史，记录时间、模式和结果，不上传或跨设备同步。
- 刷新页面后恢复本轮抽取历史、已抽对象和抽签设置。
- 用户可以暂时停用缺席成员，不需要从名单中删除姓名。
- 支持粘贴从表格复制的“小组、姓名”两列名单，并可下载 UTF-8 CSV 备份。
- 提供投屏模式，放大结果并隐藏名单编辑区。
- 支持桌面会议投屏，也能在手机浏览器完成名单编辑和抽签。
- 尊重系统“减少动态效果”设置；关闭动效时直接显示结果。

## 非功能要求

- 无后端、无登录、无第三方统计脚本、无员工数据上传。
- 中文界面；首次打开无需阅读说明即可完成第一次抽签。
- 最近两个主流版本的 Chrome、Edge、Safari 和 Firefox 可用。
- 核心抽样与解析逻辑有自动化测试；关键用户路径经过真实浏览器验证。

## 验收标准

- 输入两组各三名员工后，刷新页面名单仍存在。
- 四种模式均能得到来自正确候选范围的结果。
- 默认连续抽取不会重复；重置本轮后原对象可再次参与。
- 重复姓名、空小组、抽取数超限均有可理解的反馈。
- 页面在 390px 手机宽度和 1440px 桌面宽度下无横向溢出，主要操作可见且可点击。
